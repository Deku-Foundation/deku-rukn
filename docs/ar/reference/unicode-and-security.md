# Unicode وأمان المعرّفات

**الحالة: مذكرة بحثية؛ هذه الصفحة لا تعتمد سياسة جديدة للمعرّفات.**

في لغة تجعل العربية جزءًا أساسيًا من البرمجة، يصبح سلوك Unicode جزءًا من تصميم اللغة لا مجرد تفصيل بصري. يقبل المحلل المعجمي الحالي الحروف الأبجدية وفق خاصية Rust `char::is_alphabetic` في بداية المعرّف، والحروف أو الأرقام وفق خصائص Rust في بقيته، كما يقبل الشرطة السفلية. لا تحدد النسخة الحالية سياسة تطبيع أو معالجة للتشابه البصري أو لمحارف التحكم في اتجاه النص.

## السلوك الحالي

- ملفات المصدر بترميز UTF-8.
- يبدأ المعرّف بشرطة سفلية أو حرف تصنفه Rust أبجديًا؛ وتضاف المحارف الرقمية إلى القاعدة عند متابعة المعرّف.
- تقبل الأعداد أرقام ASCII والأرقام العربية الهندية (٠–٩) والأرقام الشرقية العربية (۰–۹).
- تُحوّل أرقام الأعداد إلى ASCII قبل التحليل العددي.
- لا تستخدم القواعد الحالية ملف تعريف Unicode القياسي `XID_Start` و`XID_Continue` ولا تطبّق تطبيعًا لأسماء المعرّفات.

هذا سلوك نموذجي أولي، وليس مواصفة مكتملة لمعرّفات Unicode.

## أساس البحث

### 1. تحديد مجموعة مقصودة للمعرّفات

تشرح [الملحق Unicode UAX #31](https://www.unicode.org/reports/tr31/) خصائص المعرّفات الموصى بها وكيفية تخصيصها. ينبغي تقييم ملف تعريف مبني على `XID_Start` و`XID_Continue` مع قاعدة موثقة للشرطة السفلية، بدل اعتماد جميع الحروف والأرقام الأبجدية بوصفها سياسة نهائية.

يجب اختبار علامات التشكيل العربية، والمحارف المركبة، والحروف الفارسية، والاختلاف بين الياء والكاف العربية والفارسية، ومحارف الربط، والمحارف خارج المستوى الأساسي، والمحارف غير المدعومة. يجب تحديد المجموعة المقبولة بواسطة خصائص Unicode وإصدارها، لا الادعاء بأن «كل Unicode مدعوم».

### 2. اتخاذ قرار صريح بشأن التطبيع

يعرّف [الملحق UAX #15](https://www.unicode.org/reports/tr15/) أشكال تطبيع Unicode. يحتاج تصميم اللغة إلى تحديد ما إذا كانت الكتابات المتكافئة قانونيًا تُعامل كاسم واحد، وهل يحدث التطبيع قبل البحث عن المتغير، وكيف تُحافظ رسائل الخطأ على الكتابة الأصلية.

لا ينبغي تطبيع محتوى النصوص المقتبسة تلقائيًا لمجرد اختيار تطبيع أسماء المعرّفات؛ فالأسماء والنصوص لها دلالات مختلفة. عند إضافة التطبيع، يجب تثبيت إصدار Unicode وإضافة اختبارات توافق وتوثيق أي تصادم محتمل بين أسماء كانت مختلفة.

### 3. التعامل مع التشابه البصري واختلاط الأبجديات

تشرح [المواصفة الأمنية UTS #39](https://www.unicode.org/reports/tr39/) آليات كشف النصوص المتشابهة بصريًا والمُعرّفات المشبوهة التي تمزج أنظمة كتابة مختلفة. يمكن لأداة فحص مستقبلية إصدار تحذير عندما يبدو اسمان متشابهين أو يمزجان أبجديات بصورة غير متوقعة.

الحظر الكامل للحروف اللاتينية قد يعيق التكامل مع النظام البرمجي المحيط. الأفضل ملف معرّفات موثق وتحذيرات مفيدة بدل إعادة كتابة الأسماء بصمت أو رفض كل اسم يمزج الأبجديات. القرار النهائي ما زال مفتوحًا.

### 4. إظهار محارف الاتجاه غير المرئية

يحدد [الملحق UAX #9](https://www.unicode.org/reports/tr9/) خوارزمية اتجاه النص ثنائي الاتجاه. ينبغي أن يحدد ركن كيفية اكتشاف محارف تغيير الاتجاه غير المرئية أو عرضها داخل المصدر والتعليقات والنصوص ورسائل الخطأ. يجب أن تجعل أدوات المراجعة هذه المحارف قابلة للفحص من دون إفساد عرض العربية الصحيحة.

## مسار القرار المقترح

1. كتابة مقترح يضم أمثلة لمعرّفات صحيحة وخاطئة وملتبسة.
2. مقارنة ملف مبني على UAX #31 وملف أضيق يراعي العربية والسلوك الحالي المبني على خصائص Rust.
3. إضافة اختبارات لعلامات التشكيل وأزواج التطبيع واختلاط الأبجديات ومحارف الاتجاه ومجموعات الأرقام ومواضع الأعمدة.
4. مراجعة أثر التوافق والترحيل قبل تغيير طريقة البحث عن الأسماء.
5. تسجيل النتيجة كقرار مقبول أو مرفوض وتثبيت إصدار بيانات Unicode المستخدم.

## شروط ما قبل إصدار مستقر

- تحديد صياغة معيارية للمعرّفات وإصدار Unicode المعتمد.
- وجود مجموعة اختبارات توافق مشتركة بين المواصفات والتنفيذ.
- اختبار سلوك التطبيع والتشابه البصري وتوثيقه.
- مراجعة التعامل مع المحارف غير المرئية في المحررات والطرفيات والتشخيصات.
- نشر ملاحظات التوافق والترحيل عند تغيير مجموعة المعرّفات.
